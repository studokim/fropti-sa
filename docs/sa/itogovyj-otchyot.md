## О системе

Fropti («fresh & optimal») — мобильное приложение, которое планирует питание за пользователя: автоматически составляет меню из рецептов с учётом продуктов, уже имеющихся дома, ведёт «холодильник» и список покупок, минимизируя остатки и выброшенные продукты. Приложение — offline-first: рецепты, холодильник, меню и сама генерация работают без сети; сервер нужен только для маркетплейса, оплат и обновления каталогов.

Приложение уже было придумано (хотя и не реализовано) ранее. Для модульного задания предлагается развитие: доставка домашней заморозки.

В занятые дни пользователь может не готовить, а заказать готовое замороженное блюдо домашней кухни (не полуфабрикат — блюдо полностью приготовлено и требует только разогрева) у повара-исполнителя из своего района. Собственной логистики платформа не содержит: доставку выполняет сторонний подрядчик (например, Яндекс.Доставка). Заморозка снимает главное ограничение классической доставки еды — блюдо не нужно есть сразу после приготовления, поэтому недельный набор можно привезти одной доставкой, а работа в пределах одного района делает такую доставку дешёвой даже с учётом комиссии подрядчика.

Подробнее — в [концепции системы](https://wiki.yandex.ru/homepage/2025-hci-students/2-kurs/sistemnyjj-analiz-i-razrabotka-slozhnyx-informacio/modulnoe-zadanie-1/mobilnoe-prilozhenie-dlja-planirovanija-domashnego/).

### Муравьев Кирилл

- Техническое задание на экран «Карточка замороженного блюда»: элементы, офлайн, оплата, ошибки, статусы заказа. Макет карточки и шторки. После сверки поправил сроки под реальную заморозку, формат дат, время резерва, сумму на кнопке «Заказать» для одной порции, кэш отзывов и КБЖУ.
- Каркас итогового отчёта.
- Два сценария использования: оформление и оплата заказа; повтор заказа, когда цена или остаток порций уже не совпадают с тем, что пользователь видел на карточке.
- Рефлексия. Учебный API заказа стоит отдельно от уже работающего бэкенда Fropti: в текущем сервисе сценария заморозки ещё нет, и встраивать его в существующий код ради модульного задания было бы дольше, чем поднять контракт рядом.
- Репозиторий и выкладка. API поднимается отдельным контейнером рядом с текущим сервисом; Caddy проксирует его так же, как существующий `/api`.

### Айзенберг Семён

- Диаграммы, которые не повторяют контейнерную схему из концепции: последовательность оплаты, состояния заказа и место экрана в клиентском приложении.
- OpenAPI на пять методов (`GET` и `POST`) и Swagger UI в том же процессе, что и API.
